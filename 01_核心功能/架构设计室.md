# 架构设计室（v2.5 新增）

> 本室回答两个问题：这个技能是怎么搭起来的（架构图），为什么这样搭（设计哲学）。供维护者升级技能时对齐设计意图，也供使用者理解技能的边界与逻辑。设计理念与龙助理四层模型同源：身份驱动运转，运转调度模块，模块沉淀知识。

## 一、架构图

### 1. 五层架构总览

```text
L1 内核路由层 —— SKILL.md
    │   场景路由 · 触发意图表 · 确诊人群分流 · 重要原则 · 隐私声明
    │
    ├──▶ L2 评估轨道
    │        01_核心功能/评估流程.md：四层递进（身份场景 → 引导采集 → 量化评分 → 方案输出）
    │        量化工具接入 · 🟢🟡🔴 分级结论
    │
    ├──▶ L2 追踪轨道
    │        档案四件套（profile.json / daily_log.csv / goals.md / trend.md）
    │        21:00–21:30 日报 · 触发接入与降频熔断 · CGM 蓝牙报警事件采集
    │
    │            两轨道按需下沉调用 ▼
    │
    ├──▶ L3 专业模块层 —— 02_健康模块/（12 个模块，单次调用 1–3 个）
    │        体质辨识 · 代谢综合征 · 饮食调理 · 运动处方 · 皮质醇 · 起居节律
    │        中医自助 · 医疗资源 · 量化评估工具 · 护眼护嗓 · 微习惯管理
    │
    ├──▶ L4 知识库层 —— 03_参考资料/
    │        血糖管理术语与指标（CGM 十项指标 / 波动五参考值 / AGP 五步法）
    │        年度体检清单（必查项目与异常分级）
    │
    └──▶ L5 输出层
             01_核心功能/报告模板.md（7 个模板）
             本地健康档案落盘（云端环境写入授权工作目录）
```

### 2. 一次典型调用的数据流（以"用户上传 CGM 周报"为例）

```text
SKILL.md 识别场景（CGM 报告解读）
  → 路由 L4 血糖术语手册（锁定口径：TIR 分层 / GMI 公式 / APP 口径差异）
  → 按手册口径用代码完成公式换算
  → 模板七组织输出：充分性声明 → 十项指标表 → 分级结论 → 防误读提示
  → 建议入档（daily_log.csv extra 列 + trend.md 周期对比）
  → 次日追踪轨道日报引用本次结论
```

评估类咨询走 L2 评估轨道主链，追踪类咨询走 L2 追踪轨道主链，两轨共享 L3/L4；跨模块需求（如"血糖高怎么吃"）由 L1 路由同时调度代谢模块与饮食模块。

### 3. 层间调用规则

| 规则 | 说明 |
|------|------|
| L1 只路由不计算 | SKILL.md 不承载具体健康知识，防止入口层膨胀 |
| L2 是流程骨架 | 评估 / 追踪只定流程与协议，专业判断全部委托 L3 |
| L3 单次限 1–3 个模块 | 控制上下文长度，按 SKILL.md 资源导航表精准选择 |
| L4 只存口径不存流程 | 术语手册 / 体检清单是"标准答案"，被任意轨道引用 |
| L5 模板即协议 | 输出结构固定，保证跨会话、跨用户输出可预期、可归档 |

## 二、设计哲学

### 1. 法律人优先，不是健康百科
久坐、高压、开庭不规律、长时间用声用屏，是所有建议的第一约束条件。通用健康建议必须经过"法律人场景适配"才能输出——同样一句"多运动"，在这里必须回答开庭日怎么办。

### 2. 双轨闭环
评估给判断，追踪给改变。只有评估没有追踪，报告就是一张好看的纸；只有追踪没有评估，数据堆不出结论。两轨共享档案与口径，互为输入。

### 3. 分级干预，不越界
🟢 保持预防、🟡 调整监测、🔴 明确就医。自助方案给足，就医信号讲清，不硬扛也不制造焦虑。技能做健康管理，不做诊断，边界写在每一份输出里。

### 4. 循证与口径统一
每个数值标出处与版本，阈值只认共识原文；口径不明的数据标注"待确认"，禁止补估算值。宁可慢一步核实，不编一个漂亮的数字。

### 5. 防误读先于给结论
GMI 不等于化验糖化、APP 口径与共识口径不同、CV 会因均值下移而机械升高——数字本身不说谎，误读才伤人。防误读提示是输出的组成部分，不是附录。

### 6. 操作化到 2 分钟
建议必须落到"什么时候做、做多久、怎么做"，否则等于没说。行为改变靠设计不靠意志力：事件锚点、微习惯配方、if-then 预案、降级方案，把坚持变成系统问题。

### 7. 数据主权与不打扰
档案写入用户授权目录，位置如实告知；连续漏记先降频、后暂停询问，追踪是服务不是监控。CGM 报警兜底实时安全，日报只做每日回顾——两条线各司其职，不重复打扰。

## 三、审计与进化

### 1. 审计机制：技能怎么体检

| 审计类型 | 做法 | 产出 |
|---------|------|------|
| 对照评测 | 典型 case × 对照组（裸能力）/实验组（加载技能），如 eval-20260912 运行 | 逐 case 增量证据与改进清单 |
| 结构审计 | 版本号三方一致（frontmatter / 正文 / README）、模块索引与实际文件对齐、资源导航表覆盖完整 | 缺漏清单（如 v2.4.1 修复的索引遗漏） |
| 输出抽检 | 对已生成的报告 / 日报复核口径、数值与模板符合度 | 口径漂移预警 |

审计发现的问题统一分级（P0 缺陷必修 / P1 显著提升 / P2 结构增强），进入修复闭环：修复 → 打包 → 复测 → 关闭。

### 2. 进化机制：技能怎么升级

- **版本语义**：minor = 新模块 / 新轨道（v2.3 血糖手册、v2.4 微习惯、v2.5 架构室）；patch = 修复与增强（v2.4.1、v2.4.2）
- **进化来源优先级**：真实使用反馈 > 对照评测发现 > 结构审计 > 前瞻学习（如 v2.3 的术语学习）
- **升级纪律**：升级前先读本室对齐设计意图；不破坏层间调用规则与七条哲学；每次改动入 CHANGELOG；三线同步（技能文件 / GitHub / 平台草稿）后沉淀记忆
- **不做的事**：不为升级而升级；不堆没人问的功能；不为了好看的版本号拆分本应一次完成的改动
